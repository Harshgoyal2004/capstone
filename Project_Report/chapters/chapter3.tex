\section{Requirements}

\subsection{Functional Requirements}

In order for the system to be clinically relevant, the following functional requirements should be fulfilled:

Firstly, the application should include a chat-style interaction for managing the medical intake interview process and acquiring patient data (age, gender, symptoms, and markers of diabetes) through NLP, rather than by means of rigid forms.

Secondly, the architecture should accept direct uploads of files and process the data included therein, namely, in the form of \ac{csv}-based electrocardiogram waveforms and acoustics in standard audio file formats.

Thirdly, the operational process must simultaneously employ neural inference from the models ECGNet, DiabetesNet, and ParkinsonNet, each one responsible for assessing the risk of cardiac, metabolic, and motor diseases, respectively.

Fourthly, the system should produce a combined triage state that identifies the urgency of the patient as either routine, checkup recommendation, or urgent consultation.

Finally, the rendering component of the application should present the results of such screenings by means of conversational language produced via the Gemini LLM, while always identifying output as preliminary screening.

\subsection{Non-Functional Requirements}

To ensure performance and deployment, the following non-functional parameters are mandatory:

Firstly, latency should be optimized through loading all main inference model structures into memory directly at server boot-up time.

Secondly, the backend should be able to process all network activity asynchronously through dedicated FastAPI endpoints, preventing request queueing and thus ensuring performance.

Thirdly, network resilience is assured through reliable Gemini \ac{llm} fallback chain (cascading through commercial API tiers) that mitigates issues caused by request limits.

Fourthly, the entire user experience should run natively in standard web browsers without requiring expensive GPU cluster access.

Finally, absolute security in terms of live API traffic must be enforced with strict \ac{cors} configuration policies.

\section{Feasibility Study}

\subsection{Technical Feasibility}

Each chosen technology is open-source, mature, and widely available. PyTorch $\geq$ 2.0 is capable of running all required inference processes purely on CPU, which makes the project suitable for execution on standard cloud server instances (such as Render free tier). The free-tier version of the Gemini API is sufficient for project demonstration purposes. FastAPI is designed to perform asynchronous I/O tasks in production environment. Streamlit is modern, highly interactive, and relatively easy-to-use frontend framework.

All required signal processing tasks (such as Butterworth filtering, R-peak detection, and features extraction from the audio) can be performed using standard SciPy and librosa libraries, both of which are highly-maintained Python packages.

\subsection{Economic Feasibility}

All code development has been carried out utilizing only free-tier cloud computing resources (Colab T4 GPU instance and Render deployment) and free software (open source). The use of the Gemini API free tier allows for obtaining enough quota for the demo/prototype implementation. The project does not require any proprietary dataset or other licensed data sources.

\subsection{Operational Feasibility}

The application runs as a regular web application, requiring nothing else from users besides a browser with an internet connection. Conversational language produced by the \ac{llm} will help users enter medical data via chat, which requires no specialized skills. The system is explicitly non-diagnostic.

\section{Model Architecture Specifications}

\subsection{ECGNet — Multi-Scale Attention CNN}

ECGNet processes single-channel \ac{ecg} beat windows of fixed length (252 samples at 360 Hz, corresponding to 0.7 seconds) and classifies each beat into one of five \ac{aami} classes: N (Normal), S (Supraventricular), V (Ventricular), F (Fusion), Q (Paced/Unknown).

The model comprises three Multi-Scale Blocks, each containing three parallel Conv1d layers with kernel sizes 3, 5, and 7, followed by Batch Normalisation, ReLU activation, and a Channel Attention module. The Channel Attention module implements the Squeeze-and-Excitation mechanism:

\begin{equation}
	\hat{x}_{c} = \sigma\!\left(W_2 \cdot \text{ReLU}(W_1 \cdot \text{GAP}(x))\right) \cdot x_c
\end{equation}

where \textit{GAP} denotes Global Average Pooling, $W_1 \in \mathbb{R}^{C/r \times C}$, $W_2 \in \mathbb{R}^{C \times C/r}$ are learnable weights, $r=8$ is the reduction ratio, and \ac{sigma} denotes the sigmoid activation.

The total parameter count is approximately 487K. The model is trained using Focal Loss with $\gamma = 2$:

\begin{equation}
	\mathcal{L}_{\text{focal}} = -\sum_{c} \alpha_c (1 - p_c)^{\gamma} \log(p_c)
\end{equation}

This loss function down-weights easy (common) examples and focuses learning on hard, rare beat classes — an essential property given the severe class imbalance in the MIT-BIH dataset (72\% Normal beats).

\subsection{DiabetesNet — Tabular Deep Neural Network}

DiabetesNet is a three-layer fully connected network operating on 8 StandardScaler-normalised clinical features. The architecture is:

\begin{equation}
	z^{(1)} = \text{BN}(\text{ReLU}(W^{(1)}x + b^{(1)})); \quad \hat{y} = \sigma(W^{(3)}z^{(2)} + b^{(3)})
\end{equation}

where $x \in \mathbb{R}^8$ is the normalised feature vector, and Batch Normalisation (\ac{bn}) with Dropout (rates 0.3 and 0.2) prevents overfitting on the small (768-sample) dataset. Binary cross-entropy with logits loss is used for training:

\begin{equation}
	\mathcal{L}_{\text{BCE}} = -[y \log(\hat{y}) + (1-y) \log(1-\hat{y})]
\end{equation}

\subsection{ParkinsonNet — Voice Feature DNN}

ParkinsonNet accepts a 22-dimensional feature vector of acoustic biomarkers extracted from sustained vowel phonation. The architecture mirrors DiabetesNet with higher-capacity layers (22 $\rightarrow$ 64 $\rightarrow$ 32 $\rightarrow$ 1) and stronger regularisation (Dropout 0.4). The 22 features span fundamental frequency statistics, jitter, shimmer, noise ratios, nonlinear dynamics, and pitch entropy measures, all normalised using StandardScaler fitted to the UCI training set.
