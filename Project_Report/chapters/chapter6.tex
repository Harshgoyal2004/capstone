\section{Development Environment}

All model training was carried out on Google Colab (Python 3.10, NVIDIA T4 GPU) using the \texttt{models.ipynb} Jupyter notebook. The backend and frontend were developed locally on macOS using a Python virtual environment (\texttt{venv}). Git was used for version control, with the repository hosted at \texttt{github.com/Harshgoyal2004/capstone}.

The project structure is as follows:
\begin{verbatim}
capstone/
|-- app.py                     # FastAPI backend
|-- requirements.txt           # 14 Python dependencies
|-- Heart-model.pt             # ECGNet weights (~2.08 MB)
|-- Diabetes-model.pt          # DiabetesNet weights (~8.5 KB)
|-- Parkinson-model.pt         # ParkinsonNet weights (~20 KB)
|-- models.ipynb               # Training notebook (all 3 models)
|-- inference/
|   |-- heart.py               # ECGNet + ECG signal processing
|   |-- diabetes.py            # DiabetesNet + feature normalisation
|   +-- parkinson.py           # ParkinsonNet + voice feature extraction
|-- chat/
|   |-- groq_client.py         # Gemini LLM client + system prompt
|   +-- parser.py              # MODEL_INPUT/OUTPUT parsing + triage
+-- ui/
    +-- streamlit_app.py       # Streamlit chat UI
\end{verbatim}

\section{Implementation Specifics}

\subsection{Backend Application (\texttt{app.py})}

FastAPI configuration includes the use of \ac{cors} middleware, which allows all origins in order to facilitate cross-origin communication between Streamlit frontend and API during local development. The app uses the startup event to load all three models using \texttt{\_get\_model()} functions of respective modules.

The \texttt{/chat} endpoint implements the double pass \ac{llm} system. An important detail in its implementation is the inclusion of status notes into the latest user message indicating whether particular file types have been previously uploaded to the app:

\begin{verbatim}
if request.ecg_file_path:
    status_notes.append("The user has already uploaded an ECG file.")
\end{verbatim}

The \ac{llm} will use the presence of this note to refrain from asking about uploading the file again and to categorize it as \texttt{"provided"} in \texttt{<MODEL\_INPUT>}.

\subsection{ECG Inference (\texttt{inference/heart.py})}

The \texttt{predict()} method supports CSV inputs with a single or multiple columns, in the latter case always utilizing only the first one. Signal resampling from non-360Hz source data is performed using \texttt{scipy.signal.resample}. Output risk score is stratified into three categories using the empirically determined thresholds: Low (< 0.35), Moderate (0.35 - 0.70), High (>= 0.70).

\subsection{Parkinson Voice Inference (\texttt{inference/parkinson.py})}

The pYIN F0 estimator yields additional binary array of voiced/unvoiced segments, which is used to discard any silence or unvoiced consonant segments from further analysis of jitter and shimmer measures. All nonlinear features (RPDE, DFA, D2) are calculated using the corresponding NumPy implementations of Grassberger-Procaccia algorithm and detrended fluctuation analysis.

\subsection{LLM Prompt Engineering (\texttt{chat/groq\_client.py})}

System prompt includes four sections in total: Role definition, Data Collection Protocol (describing \texttt{<MODEL\_INPUT>} in full), Guidelines for Result Interpretation, and Safety Rules. Temperature is set to 0.7, providing a good balance between coherence and natural variation. \texttt{max\_output\_tokens} parameter is capped at 2048, sufficient for intake and interpretation responses.

\subsection{Streamlit App UI (\texttt{ui/streamlit\_app.py})}

Frontend state management relies on Streamlit's \texttt{st.session\_state} variable. It enables persistent storage of chat state in memory for sequential conversations. The state engine also keeps a cache of local file paths associated with each upload, avoiding duplicate file uploads. Finally, it stores the risk levels and triage results temporarily for displaying on the dashboard.

Custom HTML/CSS code in \texttt{st.markdown()} blocks is used for risk badges rendering, showing appropriate color coding based on level (green for low/stable, yellow for moderate/borderline/mild, red for high/elevated). Medical disclaimer modal appears on the first load.

\subsection{App Deployment (\texttt{render.yaml})}

Render.yaml describes how to deploy the app as a Docker service, mounting \texttt{Dockerfile} found at the root of the git repository as the base image. The Dockerfile runs \texttt{pip install -r requirements.txt} to install all dependencies, then starts FastAPI server on port 8000 with Uvicorn.
