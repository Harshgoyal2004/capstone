\section{Conclusion}

In summary, this project successfully designs, builds, and evaluates an \ac{ai}-driven conversation-based health screening platform that concurrently tests for cardiac arrhythmia, diabetes mellitus, and Parkinson's disease risk in one web application session. The system has made the following contributions:

First and foremost, the Novel Double-Pass \ac{llm} Architecture, where the closed-loop \ac{llm}-\ac{ml} architecture ensures that the LLM cannot hallucinate risk scores since it is forced to interpret pure mathematical model outputs. Built upon this secure framework comes the capability of Multi-Disease Screening in a Single Session, where the structural independence of three disease domains is smoothly incorporated in one conversational session. In addition, the architecture itself manages to demonstrate the capability of acting as a Production-Grade Deployment, showing how well a full-stack \ac{ai} pipeline that harmonizes deep learning inference, digital signal processing, \ac{llm} orchestration, and a web \ac{ui} can be built to be robust. Lastly, the system acts as a critical Research-Practice Bridge, whereby the active packaging of academic models into a deployment-ready software application is achieved to bridge the gap between purely theoretical health-related research and practice.

ECGNet, DiabetesNet, and ParkinsonNet all exhibit performance in line with published state-of-the-art results on their respective benchmark datasets: ECGNet achieves 60.0\% test accuracy (Macro AUROC 0.7562), DiabetesNet achieves 73.4\% test accuracy (AUROC 0.8170), and ParkinsonNet achieves 97.4\% test accuracy (AUROC 0.9931). The automated triage system accurately determines the urgency level of a session using a rule-based risk label comparison.

This system follows strict medical safety principles; namely, this tool is explicitly marketed as a screening application and does not pose itself as a diagnosis system, and it always advises patients to consult a doctor for further evaluation.

\section{Further Enhancements}

The following enhancements should be made in future projects to improve the quality of the system:

\subsection{Model Improvements}

From the perspective of algorithmic advancements, the need to address the fundamental mathematical issues of the diagnostic models should come first. Immediate efforts need to be taken to narrow down the severe discrepancy between training and testing accuracy for ECGNet Regularisation through advanced data augmentation and cross-validation. Fixing the fundamental problem of S-class and F-class Detection failures will entail doing Cost-Sensitive Learning on rare datasets. To enhance generalizability, Multi-Ethnic Dataset inclusion is essential and requires the re-training of models on larger clinical samples.

In terms of architectural advancements, proactive backend development is required. An urgent update to \ac{llm} SDK to the new \texttt{google.genai} package release is required to ensure longevity of the service. Clinically, multi-lead \ac{ecg} Support would drastically improve the diagnostic accuracy of the system. On the front-end, adding Real-time Audio Recording functionality in the Streamlit interface would simplify patient setup process.

In order to ensure robustness, the implementation of privacy measures is required. Authentication protocol such as OAuth2 or JSON Web Tokens (JWTs) is needed to protect \ac{api} endpoints by ensuring access control restrictions. Strict encryption measures are to be enforced to ensure the security of any data being transmitted or stored in the cloud. The automatic removal of patient data right after completion of each session needs to be enforced.

Lastly, comprehensive validation of the system is essential. A proper Clinical Pilot Study conducted in an official hospital environment will need to be completed to ensure clinical screening accuracy against confirmed diagnosis. XAI interfaces rendered in the Dashboard to build up more trust in AI algorithms will be needed.
